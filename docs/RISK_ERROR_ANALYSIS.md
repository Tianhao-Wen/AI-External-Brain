# 会议风险误报 / 漏报根因分析

> 数据来源：`benchmarks/results/baseline_v1/meeting_dev/meeting_results.json`（优化前，20 场会议）
> 与 `.../meeting_test_unseen/`（未暴露集，14 场）。
> 逐条明细可用 `python -m benchmarks.risk_analysis <结果目录>` 重新导出。

## 1. 总体情况（优化前，开发集）

| 项目 | 数量 |
| --- | --- |
| 标准风险 | 25 条 |
| 模型输出 | 39 条 |
| 命中（TP） | 25 |
| **误报（FP）** | **14** |
| 漏报（FN） | 0 |
| 等级标错 | 6（其中 4 条把 medium 标成 high） |

结论先行：**问题几乎全在精度侧**。模型对"哪里不对劲"很敏感，但对
"这件事是不是已经解决了 / 只是别人提的要求 / 只是背景说明"分辨不清。

## 2. 误报逐条分类

14 条误报按语言特征分成 8 类，每类都能指着原文说明为什么它不算风险：

### 类型 A｜已解决的事项被重新当成风险（1 条）

| meeting_id | 模型输出 | 原文 | 根因 |
| --- | --- | --- | --- |
| MEET-009 | 磁盘使用率告警风险 | 「今日共发生 2 起告警，均为磁盘使用率超过 80% 的阈值提醒，**已通过清理日志恢复**，当前各节点磁盘使用率均在 55% 以下」 | 依据只截取了前半句（告警发生），漏掉紧随其后的"已恢复"。模型把"曾经发生过"当成"仍然存在" |
| MEET-U07（未暴露集） | 抓取定位偏差问题 | 「上线初期出现的抓取定位偏差问题，**已通过更换视觉标定板在 4 月底彻底解决**，近三周未再复现，该风险已关闭」 | 同上；这类"复盘会"最容易触发 |

**修复**：`risk_rules` 检查依据内及**依据后一句**是否含"已解决/已恢复/已关闭/未复现"标记。

### 类型 B｜规范提醒 / 行为约束被当成风险（3 条）

| meeting_id | 模型输出 | 原文 | 根因 |
| --- | --- | --- | --- |
| MEET-012 | 需求替换绕过变更评审 | 「张伟**提醒**，替换需求要走变更评审，不能口头决定」 | 这是"要求怎么做"，不是"已经出了什么问题" |
| MEET-017 | 回访中承诺具体交付日期的风险 | 「张伟提醒回访中**不要**承诺具体交付日期」 | 同上，属于行为约束 |
| MEET-U08（未暴露集） | 供应商交付质量不达标 | 「本年度共交付 42 万条，一次通过率 91.2%，低于合同约定的 95% 质量基线，按条款**应当**扣减 5% 服务费」 | 依据里带"应当"，但整句其实在描述不达标事实 → 属于**规则误判**，见 §4 |

**修复**：依据只由指令词（提醒/要求/必须/不要/禁止/应当）构成**且**标题与描述中也没有
问题词时才丢弃。类型 B 的最后一条正是这条规则的边界，已按"宁可漏删不可误删"调整。

### 类型 C｜工作安排 / 关注项（1 条）

| meeting_id | 模型输出 | 原文 |
| --- | --- | --- |
| MEET-009 | 晚高峰订单写入压力风险 | 「王强接手值班，**重点关注**晚高峰的订单写入压力」 |

**修复**：依据是工作安排标记（重点关注/安排/下一步/待办）且无问题词时丢弃。

### 类型 D｜待评估、尚未决定的事项（1 条）

| meeting_id | 模型输出 | 原文 |
| --- | --- | --- |
| MEET-012 | 个人中心改版提前导致排期冲突 | 「陈晨提出下个迭代想把个人中心改版提前，但目前排期已满，**需要评估是否**替换掉一个低优先级需求」 |

模型把"还没有决定"写成了确定的风险事实。**修复**：待评估标记（需要评估/是否替换）且无问题词时丢弃。

### 类型 E｜假设条件下的测算（1 条）

| meeting_id | 模型输出 | 原文 |
| --- | --- | --- |
| MEET-020 | 接受现有条款的潜在损失上限约 300 万元 | 「吴静**测算如果**接受现有条款，**潜在**的一次性损失上限约 300 万元」 |

**修复**：同时命中假设词（如果/假如/若）与测算词（测算/预估/潜在）时丢弃。

### 类型 F｜背景说明与原因解释（4 条）

| meeting_id | 模型输出 | 原文 |
| --- | --- | --- |
| MEET-003 | 新增预算短期无法压缩 | 「陈晨说明增加的预算用于第三季度新功能预研，短期内无法压缩」 |
| MEET-008 | 需求优先级变化影响原规划 | 「客户对开放接口的需求优先级在最近两周明显下降，而移动端适配的诉求提前了」 |
| MEET-020 | 对方为唯一可替代供应商导致谈判空间有限 | 「周凯说明对方是唯一可替代的供应商，谈判空间有限」 |
| MEET-023 | 模块开发缺少统一设计约定 | 「王强说明主数据模块是三个人交替开发的，缺少统一的设计约定」 |

这类内容解释了"为什么会这样"，本身不是新的风险事实。**部分**被规则拦住
（依据带"说明/因为"且无问题词），**部分保留**——因为其中确实包含"缺口/限制"的语义，
强行过滤会误伤真实风险。这是当前 Precision 尚未到 90% 的主要来源。

### 类型 G｜同一事实的细分重复（2 条）

| meeting_id | 模型输出 | 已标注的同类风险 |
| --- | --- | --- |
| MEET-003 | 第三方地图服务订阅费单项超预算 | R1「本季度将超支约 45 万元」 |
| MEET-023 | 缺陷数持续上升 | R1「缺陷密度是全项目的 2.6 倍」 |

**修复**：同一 `risk_type` 且关键短语重合度高的条目合并，保留更严重的一条。

### 类型 H｜总结句 / 讨论观点（2 条）

| meeting_id | 模型输出 | 原文 |
| --- | --- | --- |
| MEET-029 | 按期交付可能性降低 | 「**以上问题**叠加，按期交付的可能性已明显降低」 |
| MEET-032 | 培训短期难以缓解风险 | 「陈晨**认为**培训周期至少一个月，短期内无法缓解」 |

**修复**：总结标记（以上问题/综上/叠加）丢弃；讨论观点（认为/建议）在有具体问题事实时保留。

## 3. 漏报分析

开发集漏报 0 条；**优化后**开发集出现 2 条漏报（Recall 100% → 92%）：

| meeting_id | 漏掉的风险 | 原因 |
| --- | --- | --- |
| MEET-003 R2 | 「暂停压测环境的执行人尚未确定」 | 新 Prompt 要求"同一件事的多个侧面只保留一条"，模型把这条并入了预算超支，未单独输出 |
| MEET-018 R2 | 「当前没有资源做双实例改造，至少要等下个季度」 | 同上，被并入单点故障 |

**判定**：这是真实的能力权衡，不是评分问题。模型对"资源约束是原因还是独立风险"的判断
与标注口径不一致。已确认这两条**不是**被确定性规则删除的（用 `diag_meeting` 复现：
规则丢弃 0 条），因此没有通过放宽规则来"找回"召回。

## 4. 确定性规则的边界（重要）

用 `python -m benchmarks.replay_rules` 在同一批预测上做**离线复放**，
可以精确量化规则层的净效果（不受模型采样噪声影响）：

| 数据集 | 无规则 P / R / F1 | 有规则 P / R / F1 | TP 变化 |
| --- | --- | --- | --- |
| 开发集（基线预测） | 0.641 / 1.000 / 0.781 | 0.735 / 1.000 / 0.848 | **不变** |
| 已暴露测试集（基线预测） | 0.650 / 0.867 / 0.743 | 0.650 / 0.867 / 0.743 | **不变** |
| 未暴露测试集（基线预测） | 0.591 / 1.000 / 0.743 | 0.650 / 1.000 / 0.788 | **不变** |

一次中间版本的规则曾把两条真实风险误删（MEET-025 R2、MEET-U08 R1），
根因是"只依据 evidence 判断是否在描述问题"，而真实问题往往写在标题里
（"国际化基础设施与翻译资源缺失"）。修正为"标题+描述+依据一起看"后，
两个测试集上的 TP 损失归零。

结论：**规则层的作用是兜底，不是主力**。真正把 Precision 从 64% 拉到 85% 的
是 Prompt 里的风险判定标准；规则负责把"老版本模型仍会犯的错"确定性地挡掉。

## 5. 错误类型 → 修复方式对照表

| 错误类型 | 数量（基线 dev） | 修复层 | 修复后是否仍出现 |
| --- | --- | --- | --- |
| A 已解决 | 1 | Prompt + 规则（含下一句检查） | 否 |
| B 规范提醒 | 3 | Prompt + 规则（带问题词豁免） | 个别（U08 已修正） |
| C 工作安排 | 1 | 规则 | 否 |
| D 待评估 | 1 | Prompt + 规则 | 否 |
| E 假设测算 | 1 | Prompt + 规则 | 否 |
| F 背景/原因 | 4 | Prompt（部分） | **仍有残留** |
| G 细分重复 | 2 | Prompt（合并）+ 规则（去重） | 部分 |
| H 总结/观点 | 2 | 规则 | 否 |

残留的 F 类是下一步的主要优化方向：需要判断"这句话是在解释原因，还是在陈述一个新的坏消息"，
比当前的关键词规则更依赖语义理解。
