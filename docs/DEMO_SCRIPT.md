# 演示脚本（Demo Script · 9 个镜头）


> **命名现状（2026-11 更新）**：本报告记录的是当时的事实。此后 Python 包已从 `wendream/`
> 迁移为 `aieb/`，命令从 `wendream` 改为 `aieb`，环境变量前缀统一为 `AIEB_`（旧名仍可读）。
> 文中出现的旧包路径 / 旧环境变量名请以 [`MIGRATION_RENAMING.md`](MIGRATION_RENAMING.md) 为准。

> 用途：3～5 分钟讲完这个 Demo 的核心价值。每一镜都给出**可复现的输入**与**预期结果**。
>
> 关于视频：**本仓库没有附演示视频**（我没有录制）。本文档是录屏用的分镜脚本 + 操作清单；
> 录制方法见文末第 10 节。文中所有预期结果都来自真实运行记录，不是写死的文案。
>
> 所有样例数据均为**虚构演示数据**（蓝海智造 / 华瑞精密等公司、人物、金额均与真实企业无关）。

## 0. 准备（录屏前 5 分钟）

```powershell
# 1) 启动服务（另开一个终端保持运行）
$env:DEEPSEEK_API_KEY = "sk-你的密钥"
.\.venv\Scripts\python.exe -m aieb.brain.cli --port 18888

# 2) 浏览器打开
start http://127.0.0.1:18888
```

- 建议分辨率 1440×900，浏览器缩放 100%，关闭无关标签页。
- 如果想在镜头 5 演示"真的发出邮件"，需要额外配置 SMTP 环境变量（见 README「配置」章节）；
  不配置也能演示，产品会**如实报错**并列出缺少的变量——这一点本身就是卖点。

## 镜头 1｜工作台：先给结论（约 20 秒）

- **操作**：打开首页，停在「工作台」。
- **输入**：无（数据来自前一次完整流程）。
- **预期**：四个统计非零——已上传知识文档 1 / 已分析会议 2 / 待完成任务 8 / 未解决风险 8；
  下方「最近会议」「最近待办」直接显示可执行条目。
- **旁白**：「这不是一个聊天框，是一个把知识、会议、任务串起来的工作台。左边六块功能，
  右边是当前企业真实的状态数字。」
- **截图参考**：`docs/screenshots/01-dashboard-populated.png`

## 镜头 2｜知识库：上传真实 PDF（约 25 秒）

- **操作**：左侧「知识库」→ 点击上传区域。
- **输入**：`samples/demo_company_background.pdf`（5 页，公司制度类文档）。
- **预期**：列表出现该文档，显示 `165 KB · 5 页 · 已解析`。
- **旁白**：「PDF 是真解析的：PyMuPDF 按页抽文本，页码索引一起入库，后面回答才能给页码。」
- **截图参考**：`docs/screenshots/02-knowledge.png`

## 镜头 3｜知识库问答：必须给页码（约 30 秒）

- **操作**：点开刚上传的文档 → 提问框输入。
- **输入**：`单价上调超过 8% 需要谁审批？`
- **预期**：回答给出「必须由 CEO 陈明与财务总监何敏联合审批，缺一不可」，
  并附 `[来源：demo_company_background.pdf · 第2页]`，下方有可展开的原文片段。
- **旁白**：「答案旁边永远带页码。查不到就说查不到，不允许编——这是企业场景的硬要求。」
- **截图参考**：`docs/screenshots/03-knowledge-answer.png`

## 镜头 4｜会议中心：把会议记录变成结构化结论（约 40 秒）

- **操作**：「会议中心」→ 上传会议记录。
- **输入**：`samples/demo_meeting_risk.txt`（A 类供应商质量风险专题会）。
- **预期**：自动抽出标题、会议时间、地点、参与人、决策、**4 条风险**、**5 条待办**；
  每条风险都带「原文依据」（例如"日均损失约 35 万元"）。
- **旁白**：「模型不是自由发挥，每一条风险都能点回原文那一句——这是能不能被信任的分界线。」
- **截图参考**：`docs/screenshots/04-meeting.png`

## 镜头 5｜邮件：真实 SMTP，失败也如实说（约 30 秒）

- **操作**：在该会议详情点「生成提醒邮件」→ 填收件人 → 确认发送。
- **输入**：收件人填你自己的邮箱（演示用）。
- **预期（两种都算正常）**：
  - 已配置 SMTP：提示「已发送至 …」，真实投递成功（取证见 `docs/email_send_evidence.md`）。
  - 未配置 SMTP：提示「未配置 SMTP 邮件服务，缺少环境变量：AIEB_SMTP_HOST…」，**不会假装成功**。
- **旁白**：「发邮件这种有副作用的动作，先出草稿让你核对，再发；发不出去就把原因说清楚。」
- **截图参考**：`docs/screenshots/05-email-draft.png`、`06-email-result.png`、`17-email-sent.png`

## 镜头 6｜冲突会议：系统敢说"你们口径不一致"（约 35 秒）

- **操作**：继续在会议中心粘贴会议记录。
- **输入**：`samples/demo_meeting_conflict.txt`（预算口径冲突 + 责任人缺失）。
- **预期**：风险区出现「采购预算口径不一致」「暂停新增订单执行口径冲突」，
  待办的负责人/截止时间显示「待确认」，并说明是原文缺失。
- **旁白**：「这份记录里两个人给的预算数字对不上。产品没有替他们编一个数字，而是把矛盾点拎出来，
  把缺的责任人标成待确认。」
- **截图参考**：`docs/screenshots/07-meeting-missing.png`

## 镜头 7｜待办：状态能改、刷新还在（约 20 秒）

- **操作**：「待办事项」→ 改一条状态为「已完成」→ 按 F5 刷新。
- **预期**：状态变更立即生效，刷新后仍为「已完成」；支持按状态/优先级筛选。
- **旁白**：「会议开完不是结束，待办要能落地、能被追踪。」
- **截图参考**：`docs/screenshots/08-todos.png`、`09-todos-after-reload.png`

## 镜头 8｜长期记忆：换个新对话还记得（约 35 秒）

- **操作**：「AI 对话」→ 新建会话。
- **输入**：`上一次供应商评审会的时间、参与人和主要决策是什么？`
- **预期**：能召回上一场会议的时间、参与人、关键决策（如"暂停新增订单""单价上调暂不审批"），
  并说明信息来源是长期记忆中的会议事实。
- **旁白**：「关掉页面、换新会话，它还记得上一场会——记忆是跨会话的结构化事实，不是把聊天记录塞回去。」
- **截图参考**：`docs/screenshots/12b-memory-recall.png`

## 镜头 9｜汇报 PPT：真的生成、真的能打开（约 30 秒）

- **操作**：在对话里说「把这次供应商风险复盘做成汇报 PPT」，或直接触发 PPT 生成。
- **输入**：基于镜头 4 的会议。
- **预期**：生成 `.pptx`（约 6 页：封面 / 结论 / 风险 / 待办 / 数据表 / 下一步），
  出现下载卡片，点击可下载；用 PowerPoint 打开无错位、无溢出（校验记录见 `docs/pptx_verify_report.md`）。
- **旁白**：「不是给个 Markdown 让你自己排版，是直接产出能交给领导的文件。」
- **截图参考**：`docs/screenshots/15-ppt-card.png`、`docs/screenshots/ppt-slide-0*.png`

## 10. 可选彩蛋（时间富余时加）

| 场景 | 输入 | 亮点 |
|---|---|---|
| 联网搜索 | 「请联网查一条最近的 AI 相关新闻，给出标题、日期和链接」 | 带来源媒体、发布时间、可点击链接；没给日期会明确说"未标注" |
| 移动端 | 浏览器切 390px 宽 | 侧栏自动转横向导航，无横向滚动 |
| 错误处理 | 上传一张 `.png` | 提示"暂不支持 .png 文件，请上传 PDF 或 TXT"，且不污染已解析列表 |

## 11. 录制方法（如果要做视频）

1. 用 OBS Studio（免费）或 Windows 自带 `Win + G` 录制屏幕；
2. 按上面 9 个镜头顺序操作，每镜之间不要剪掉"思考时间"——真实模型有 3～15 秒延迟，
   剪掉反而像假的；
3. 建议时长 3.5～5 分钟，不做配音也可以，用字幕标出每镜标题即可；
4. **不要提前把答案写进输入框再假装实时回答**，也不要伪造发送成功提示。

## 12. 常见追问与答法

| 追问 | 回答要点 |
|---|---|
| PDF 是真解析吗？ | 是。PyMuPDF 按页抽文本，页码随分块入库，回答引用到页。扫描件会明确提示"无可提取文字"。 |
| 会不会编造？ | 检索不到时明确说没找到；会议风险必须给原文依据；冲突和缺失会标"待确认"。 |
| 邮件真发了？ | 已配置 SMTP 时真发，取证在 `docs/email_send_evidence.md`；未配置时如实报错。 |
| 数据和隐私？ | 全部落在本地 `.aieb/`，不入库不上传；密钥只从环境变量读。 |
| 为什么不做成全自动 Agent？ | 有副作用的动作（发邮件、删数据）保留人工确认，避免"AI 自己闯祸"。 |
| 边界在哪？ | 见 README「已知限制」与 `docs/TEST_REPORT.md` 的失败项说明。 |
